### M5.1 notes (greybox mall)
- Layout = data (`Editor/Mall/MallLayout.cs`), GDD 8 "hand-built layout, randomized contents": 12 x 10
  tiles of 4 m (48 x 40 m), three 4 m stories, street front south. Atrium x 4..7, z 3..6 open through
  floors 1-2 (glass skylight, cosmetic), walkway ring x 3..8, z 2..7 on floors 1-2 (Balcony sections,
  `Walk_*`), floor-1 bridge across the atrium at z = 5.
- Zones (tag used by loot spawning): ground Concourse, Electronics, Clothing, FoodCourt, Jewelry,
  Security(office), LoadingBay(stock); floor 1 Furniture, Toys, FoodTerrace, Electronics2, Stockroom;
  floor 2 Cinema, Boutique(jewelry), Gallery (jackpot, weak floor), Offices, StairTop.
- Routes: Escalator_G1 (atrium floor -> bridge west end) and Escalator_12 (bridge east end -> floor-2
  ring) are collapsible Stair sections (showcase); the service stairs in the loading bay/stockroom corner
  (Stairs_G1 down-south from the loading bay's back, Stairs_12 north from the stockroom) never collapse
  (GDD 6.4). Doors 1.4 m; wide 3.5 m doors on the main entrance, loading bay (exterior + concourse),
  stockroom and gallery: the routes for pianos/statues. Windows on floors 1-2 = future rope points.
- Ground tiles can't collapse (no basement); every upper tile and escalator can. Authored weak spots:
  gallery floor (capacity x0.5-0.55), bridge middle (x0.6). Stability 0.75, seed 1 until runs set them.
- Builder split: MallBuilder (tiles, roof, exterior, lights), MallFlights, MallWalls (partitions from
  zone boundaries + door table, railings at every void edge except flight openings, perimeter with the
  exterior opening table), MallPopulator (spawns in the south parking lot, network objects, surfaces,
  structure via the shared `StructureSceneSetup`, also used by TestBuilding now). Lighting: flat ambient
  + one shadowless point light per zone.
- Build scenes: TestBuilding (first, still the default) then Mall. The run flow (5.3/5.4) decides which starts.

### M5.2 notes (loot spawning)
- `LootDefinition.SpawnTags` (store kinds = mall zone tags) + `Jackpot`. `LootSpawnPoint` (tag, carry
  class range, jackpot flag). `LootSpawnPlanner` (pure, seeded): shuffles jackpot points and uses 1-2
  (`LootSpawnConfig` JackpotsMin/Max) with jackpot items only; every ordinary point fills with
  FillChance 0.6, picking by Rarity among items whose tags and class fit; every point draws its random
  numbers whether used or not, so one point never shifts another.
- `NetworkLootSpawner` (Networking, scene object): host only, on server start: plans from its seed,
  instantiates from `LootCatalog` (Data/Loot/LootCatalog.asset, written by the prefab generator: runtime
  definition -> prefab map), rolls the value seed before `Spawn()`; clients get NGO spawns. F1 shows
  seed/count/total value. Seed is a field until the run flow sets it (`SetSeed`).
- Mall points (`MallLootPoints`): every other tile in stores, one in three in open areas, one Heavy spot
  per store, jackpot points in the gallery (floor 2), furniture (floor 1) and loading bay. Seed 1:
  88 items on 143 points, ~$313k in the building.
- New items: diamond ring, pearl necklace, smartphone, game console, collector's figure, desktop PC,
  large painting, espresso machine, grandfather clock (Heavy), film projector (Heavy). Spawn tags are
  only written into definitions that have none (tuning in the inspector is kept).

### M5.3 notes (truck + extraction)
- `RunState` (Extraction, host-spawned NetworkObject `Prefabs/Network/RunState`, by the scene's
  `RunDirector` whenever this machine hosts): NetworkVariable `RunNetState` (phase Running/Honking/
  Departed, quota, haul, seed, cargo volume/capacity, window end + honk end in server time). Host tallies
  the truck every 0.25 s. `ExtractionConfig` (Data/Extraction): quota $40,000, window 15 min (soft; 5.6
  escalates after), honk 10 s, cargo 14 m3 of item bounding boxes, ignition range 3.5 m.
- `TruckCargo` (scene truck, `TruckBuilder`): bay trigger (loot whose centre is inside counts), ride
  zone (bay + cab), ignition. `TruckIgnition` is the first `IUsable` (Core): PlayerInteractor targets
  non-loot usables and the HUD shows "[E] ..."; Use asks the host (`RequestDepartRpc`), which checks the
  phase, that the sender's player is within range of the ignition, and that the cargo isn't overloaded.
- Departure (host): items in the bay + pockets of players in the ride zone (ragdolled: body position)
  become `RunResults` (name, start value, final value, pocketed; per player extracted / pocket value
  lost) sent to everyone by `ResultsRpc`; phase Departed. Left-behind players lose their pockets (GDD 10).
  `RunState.RunStatsSource` is the hook for 5.4's funny stats.
- Truck: open-backed bay with a ramp facing the loading bay's wide east door, ignition lever on the bay's
  front wall, horn (placeholder synth) every 1.5 s while honking. `RunHud`: haul/quota (green when met),
  cargo m3 (red when overloaded), window clock / "WINDOW CLOSED", "TRUCK LEAVES IN n - GET IN!".

### M5.4 notes (appraisal + next run)
- `AppraisalScreen` (all machines, OnGUI, frees the cursor): items (found at / damage / worth now,
  pocketed marked), haul vs quota (MET/MISSED), run time, who made it out (and pocket value lost), funny
  stats; host gets "Next run", clients "Waiting for the host".
- `RunStats` (host, owned by RunDirector, begins on each run's loot spawn): blames damage on whoever held
  the item within 5 s (a throw counts; a shatter counts what value was left), most expensive item
  broken + by whom, butterfingers (most value broken), longest fall (from replicated grounded state),
  floors that gave way, items left in the building. Plugged in via `RunState.RunStatsSource`.
- Next run happens in place (no scene reload, nobody reconnects; the session/bootstrap design ties the
  NetworkManager to the scene): `RunDirector.StartNextRun` (host) despawns the RunState, re-rolls the
  structure with the new seed (generation bump restores collapsed floors on every machine), despawns
  every NetworkLoot and spawns a new run from the seed, and sends each player back to their spawn slot
  (`NetworkPlayer.ServerRespawn` -> owner RPC: recover from ragdoll, teleport, face the spawn's way).
  `RunDirector.RunStarted(seed)` is the hook for monsters/danger. Measured < 3 s.
- Builds now open in the Mall (first build scene); TestBuilding stays in the build for nettests.
  `NetTestRunner` loads the scenario's scene first (`INetTestScene`, default TestBuilding).
- Nettest `run` (Mall): same seed/loot on all, host loads cargo -> haul on every screen, a client starts
  the truck from the bay, one client stays out; every machine gets the same results (haul, who's
  aboard); host starts the next run; clients find themselves on their spawn with a new seed and haul 0.

### M5.5 notes (The Blind One)
- NavMesh: `NavMeshSurface` on the mall root baked by the builder (physics colliders; players, loot,
  debris, triggers excluded; `ignoreNavMeshObstacle = false` or every collapsible tile is skipped) into
  Scenes/Mall_NavMesh.asset. No runtime rebakes (decision log): every collapsible tile/escalator has a
  `SectionNavCarver` (disabled carving NavMeshObstacle) that turns on when it collapses, off on restore.
- `BlindOne` (Threats, NetworkObject prefab Prefabs/Threats/BlindOne, server-authoritative
  NetworkTransform, NavMeshAgent enabled on the host only): hears `NoiseSystem` events (radius x
  hearing scale x 0.6 per wall between its head and the noise, `Hearing.Perceive`), `BlindOneBrain`
  (pure): Wander -> Investigate the loudest recent noise (pull fades over 8 s) -> listen 4 s -> Wander;
  Hunt at 4.2 m/s when a noise is >= 0.45 or 3 noises within 5 s; silence for 6 s -> Investigate. Kills
  any living player within 1.2 m (horizontal, |dy| < 1.8), then pauses 2.5 s. State replicated; clicks
  (placeholder synth) on every machine, faster when hunting. F1: state, pull, heard-noise lines.
- Death: `NetworkPlayer.IsDead` (server-written): owner ragdolls and stays down (`PlayerRagdoll.HoldDown`),
  motor/interactor off, "YOU DIED"; host drops their pocket loot where they died (GDD 11;
  `FreeOrphan` now unpockets through the holder). Dead players aren't extracted ("died in there" in the
  appraisal). Everyone dead -> the run ends. Next run revives everyone (`ServerRespawn`).
- `ThreatDirector` (host): each run, despawns old threats and spawns one Blind One 45 s in at a seeded
  `ThreatSpawnPoint` (cinema floor 2, loading bay, food court). `Spawn()` is public for danger (5.6).
- Ghost spectating for the dead is M6.7; for now the camera stays with the body.

### M5.6 notes (danger)
- `DangerConfig` (Data/Extraction): +1 level per 180 s; when the 15 min window closes +2 at once and
  then a level per 90 s; max 6. Per level: overloaded sections drain +25 % faster
  (`StructureSimulation.DangerDecay`), monsters hear +15 % / move +8 % further/faster; level 3 adds a
  second Blind One (once the first is out). Every 12 s the host ages `level` random collapsible
  sections by 8 % health, never below 30 % (`StructureSimulation.AgeRandomSections`): creaks and
  cracks, but weight finishes the job.
- Replicated as `RunNetState.Danger`. Shown subtly (GDD 9), never as a number (F1 shows it): on each
  level-up every machine hears a building-wide groan and radio static and the point lights flicker
  for 1.6 s. A new run (new RunState) is calm again.
- `DangerDirector` lives on the mall's Threats object next to `ThreatDirector`.
