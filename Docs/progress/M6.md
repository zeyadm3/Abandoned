### 6.0 Session travel (decision)
Players join only at HQ and must stay connected HQ -> run -> HQ. Today the NetworkManager belongs to
its scene (bootstrap destroys it on unload), NGO scene management is off, and nothing persists.
Chosen: keep NGO scene management OFF and run our own travel:
- The first session scene's NetworkBootstrap (+ NetworkManager, SteamLobby, panels) becomes the
  persistent session (DontDestroyOnLoad). A level scene loaded later deletes its own copy of those
  objects if a persistent session exists, so every level still works on its own in the editor/tests.
- Player objects are kept across loads (DontDestroyOnLoad on spawn).
- `SessionTravel` (persistent NetworkObject, host-spawned): host orders "load <scene>"; every machine
  loads it (Single mode); clients report ready; the host's level directors (structure sync, run state,
  loot, threats) only spawn once every machine has the level loaded (`SessionTravel.LevelReady`),
  then everyone is placed on the level's spawn points.
- Joining: approval refuses while away from HQ ("join when the crew is back at HQ"); the Steam lobby
  is set unjoinable during runs.
- ReturnToMenu reloads the HQ (first build scene).
Why not NGO scene management: it would need every level object rebuilt around NGO's scene events and
the in-scene object ids, and the run flow already spawns everything dynamically; the custom flow is
smaller and keeps the per-scene editor workflow.
