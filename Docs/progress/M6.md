### 6.0 Session travel (decision)
Players join only at HQ and must stay connected HQ -> run -> HQ. Today the NetworkManager belongs to
its scene (bootstrap destroys it on unload), NGO scene management is off, and nothing persists.
Chosen: keep NGO scene management OFF and run our own travel:
- The first session scene's NetworkBootstrap (+ NetworkManager, SteamLobby, panels) becomes the
  persistent session (DontDestroyOnLoad). A level scene loaded later deletes its own copy of those
  objects if a persistent session exists, so every level still works on its own in the editor/tests.
- Player objects are kept across loads (DontDestroyOnLoad on spawn).
- `SessionTravel` (persistent NetworkObject, host-spawned): host orders "load <scene>"; every machine
  loads it (Single mode); clients report ready; the host's level directors (structure sync, run state,
  loot, threats) only spawn once every machine has the level loaded (`SessionTravel.LevelReady`),
  then everyone is placed on the level's spawn points.
- Joining: approval refuses while away from HQ ("join when the crew is back at HQ"); the Steam lobby
  is set unjoinable during runs.
- ReturnToMenu reloads the HQ (first build scene).
Why not NGO scene management: it would need every level object rebuilt around NGO's scene events and
the in-scene object ids, and the run flow already spawns everything dynamically; the custom flow is
smaller and keeps the per-scene editor workflow.

### M6.0 notes (session travel)
- `NetworkBootstrap`: the first scene-session bootstrap becomes `Persistent` (DontDestroyOnLoad with its
  NetworkManager, SteamLobby, panels, ReturnToMenu); any later level's own copy deactivates and destroys
  itself (its NetworkManager immediately, so it never takes `NetworkManager.Singleton`). Level components
  find the session with `NetworkBootstrap.Resolve(ownRef)`. Tests call `DestroyPersistent()` (unhooked,
  so it isn't a "game ended" and leaves no notice) before loading a scene.
- `SessionTravel` (Prefabs/Network/SessionTravel, spawned by the bootstrap when hosting starts, DDOL):
  NetworkVariables level name + travel id. `Travel(scene)` (host): despawns every spawned object except
  players and itself, bumps the id, loads the scene; clients follow (also on join if their scene differs)
  and `ReadyRpc` when loaded. `SessionTravel.LevelReady` gates RunDirector and StructureNetSpawner (and so
  loot, run state, threats). When everyone is in, the host respawns each player on the level's spawn for
  their slot. Players are DontDestroyOnLoad.
- Limitation: in-scene placed NetworkObjects (TestBuilding's hand-placed loot) only spawn when hosting
  starts, not after travelling into a level; real levels (Mall, HQ) spawn everything dynamically, so the
  HQ must not have in-scene NetworkObjects.
- `RunDirector.ForcedSeed` / `-seed N` replays a run; PlayMode tests use seed 1 unless they ask for random.
- nettest.sh keeps a failed run's logs in Logs/nettest/failed-<scenario>-<time>/ (the rare loot flake).
