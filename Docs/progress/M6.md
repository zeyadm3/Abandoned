# M6 — The Company (detailed notes)

## Plan (autonomous build; PLAYBOOK M6, GDD 12-14)
Order: 6.0 session travel (prerequisite) -> 6.1 HQ -> 6.2 save -> 6.3 contracts -> 6.5 progression ->
6.4 shop + equipment -> 6.7 ghost spectator -> 6.6 Stalker + Collector.

### 6.0 Session travel (decision)
Players join only at HQ and must stay connected HQ -> run -> HQ. Today the NetworkManager belongs to
its scene (bootstrap destroys it on unload), NGO scene management is off, and nothing persists.
Chosen: keep NGO scene management OFF and run our own travel:
- The first session scene's NetworkBootstrap (+ NetworkManager, SteamLobby, panels) becomes the
  persistent session (DontDestroyOnLoad). A level scene loaded later deletes its own copy of those
  objects if a persistent session exists, so every level still works on its own in the editor/tests.
- Player objects are kept across loads (DontDestroyOnLoad on spawn).
- `SessionTravel` (persistent NetworkObject, host-spawned): host orders "load <scene>"; every machine
  loads it (Single mode); clients report ready; the host's level directors (structure sync, run state,
  loot, threats) only spawn once every machine has the level loaded (`SessionTravel.LevelReady`),
  then everyone is placed on the level's spawn points.
- Joining: approval refuses while away from HQ ("join when the crew is back at HQ"); the Steam lobby
  is set unjoinable during runs.
- ReturnToMenu reloads the HQ (first build scene).
Why not NGO scene management: it would need every level object rebuilt around NGO's scene events and
the in-scene object ids, and the run flow already spawns everything dynamically; the custom flow is
smaller and keeps the per-scene editor workflow.

### M6.0 notes (session travel)
- `NetworkBootstrap`: the first scene-session bootstrap becomes `Persistent` (DontDestroyOnLoad with its
  NetworkManager, SteamLobby, panels, ReturnToMenu); any later level's own copy deactivates and destroys
  itself (its NetworkManager immediately, so it never takes `NetworkManager.Singleton`). Level components
  find the session with `NetworkBootstrap.Resolve(ownRef)`. Tests call `DestroyPersistent()` (unhooked,
  so it isn't a "game ended" and leaves no notice) before loading a scene.
- `SessionTravel` (Prefabs/Network/SessionTravel, spawned by the bootstrap when hosting starts, DDOL):
  NetworkVariables level name + travel id. `Travel(scene)` (host): despawns every spawned object except
  players and itself, bumps the id, loads the scene; clients follow (also on join if their scene differs)
  and `ReadyRpc` when loaded. `SessionTravel.LevelReady` gates RunDirector and StructureNetSpawner (and so
  loot, run state, threats). When everyone is in, the host respawns each player on the level's spawn for
  their slot. Players are DontDestroyOnLoad.
- Limitation: in-scene placed NetworkObjects (TestBuilding's hand-placed loot) only spawn when hosting
  starts, not after travelling into a level; real levels (Mall, HQ) spawn everything dynamically, so the
  HQ must not have in-scene NetworkObjects.
- `RunDirector.ForcedSeed` / `-seed N` replays a run; PlayMode tests use seed 1 unless they ask for random.
- nettest.sh keeps a failed run's logs in Logs/nettest/failed-<scenario>-<time>/ (the rare loot flake).

### M6.1-6.3 + 6.5 ledger notes (HQ, save, contracts, payday)
- `CompanyService` (Company; Prefabs/Network/CompanyService, a session prefab spawned with SessionTravel
  by the bootstrap, DDOL): host loads `company.json` from Application.persistentDataPath (company
  "Zeyad Games", bundle com.zeyadgames.abandoned) via `SaveStore` (atomic temp+replace, unreadable ->
  .corrupt + new company). Test/batch runs keep the company in memory unless `SaveFolderOverride` is set,
  so automation never touches the player's save. Replicates `CompanyNetState` (money, xp, level, missed
  quotas, runs, bankruptcies, best haul), the board seed, the selected offer, the active contract and
  the last run's `OutcomeNet`.
- Board (GDD 14): `ContractGenerator.Roll(ContractConfig, level, boardSeed, LootEstimate)` on every
  machine (deterministic), 3 offers with one modifier each (no repeats). Modifiers are data
  (`ContractModifier` assets, Data/Contracts): Power Off, Unstable (-20 % stability), Rush Job (window
  x0.6), Fragile Collection (x3 weight for High/Extreme fragility); each adds a payout bonus.
- HQ scene (first build scene, `HqBuilder`): garage with the van (`HqVan`, IUsable: "Drive to ..."),
  office with the `ContractBoard` (IUsable -> `ContractBoardScreen`, host picks, others read), shop
  counter (6.4), `HqHud` (money/debt, level/xp, missed-quota streak, today's job). No in-scene network
  objects. Players spawn in the garage.
- Run on the contract's terms: RunDirector takes the active contract's seed and stability, the
  modifier's loot fill/fragile weights (`LootSpawnPlanner` options) and `RunState.TermsSource` (quota,
  window, bonus, power). `RunNetState` now carries Window, Bonus, PowerOff; `PowerController` turns the
  level's lights off and the ambient down on every machine. Danger uses the contract's window.
- Payday (GDD 5, 13): when the truck leaves, the host applies `CompanyLedger` (haul x (1 + bonus) if the
  quota is met, else the haul minus half the shortfall = debt; xp = haul/1000 (+10 for the quota);
  3 misses in a row = bankruptcy: new company with the starter kit, bankruptcies count kept) and saves.
  The appraisal shows payout, penalty, xp, level-ups, money/debt and the streak; the host's button is
  "Back to HQ" (fresh board) instead of "Next run" when on a contract.
- Joining: `NetworkBootstrap.JoinBlocker` refuses joiners while a game that started at the HQ is out on
  a job ("join when they're back at the HQ"); the Steam lobby is unjoinable then too. ReturnToMenu loads
  the HQ. `SessionTravel.Travel` keeps DontDestroyOnLoad objects (players, travel, company).
- Fixed on the way: `Contract` serializes null strings as "" (default contract); tests end any
  persistent session before each test (SteamTestRunGuard, the assembly's run callback).
- Nettest `company` (starts at the HQ): same board everywhere, host picks, a client drives, every machine
  runs the contract's terms (quota, seed, power), same payday on every screen, home to the same fresh board.

### M6.4a notes (gear)
- Data: `EquipmentDefinition` assets (Data/Equipment; id, name, kind, price, unlock level, consumable) in
  an ordered `EquipmentCatalog` (index = network id): flashlight $50, walkie-talkie $100, hand trolley
  $400, medkit $300 (single use), planks $150 (L2, single use), noise maker $250 (L2, single use), stress
  scanner $1,200 (L3). Starter kit: 4 flashlights, 4 radios, 1 medkit, 1 trolley.
- Company stock: `CompanyService` replicates owned counts (`NetworkList<OwnedGear>`); `RequestBuy` (anyone
  at the HQ `ShopTerminal`; host checks unlock level + money, saves at once); `Consume` for single-use gear.
- `PlayerEquipment` (Player prefab): `EquipState` (2 hand slots as catalog indices, which one is in hand,
  flashlight on) written by the host; keys 1/2 pick the slot, F the light (a spot light under the eyes,
  seen by everyone). The HQ `GearRack` (+ `GearScreens`) fills slots from stock nobody else holds; gear
  changes only at the HQ. Everyone starts with a flashlight and a radio while stock lasts.
- Rules (only in a company game, i.e. one that started at the HQ: `CompanyService.RulesApply`; a level
  hosted directly plays without them): the walkie-talkie needs a radio in a hand slot
  (`NetworkVoice.RadioHolder`), solo Heavy drags need the hand trolley (`PlayerCarrier.SoloDragAllowed`,
  GDD 7.2), gear stock is shared.

### M6.4b notes (single-use gear + scanner)
- Left mouse with empty hands uses the single-use item in hand (`PlayerEquipment.UseRpc`, host-checked:
  owner, alive, hands empty): Medkit revives the nearest downed crewmate within 2.5 m where their body
  lies (`NetworkPlayer.ServerRevive` -> respawn in place); Planks spawn a `plank` utility loot item (4.4 m,
  12 kg, worth $0, never spawned in runs; `LootDefinition.Utility`) to carry and lay across a hole;
  Noise Maker (Prefabs/Equipment/NoiseMaker, host-simulated) is thrown 9 m/s forward, after 3 s shrieks
  for 8 s: loud `NoiseSource.Other` events every 0.5 s (the Blind One investigates/hunts it) and a siren
  on every machine. Used items leave the slot and the company's stock.
- Stress scanner in hand: `StressScannerHud` (owner) shows the section looked at (or stood on): stage,
  health % (colour-coded) and load/capacity, from the replicated structure.
- Rope (lower loot through holes) is deferred (needs a winch/physics design); not in the shop.
