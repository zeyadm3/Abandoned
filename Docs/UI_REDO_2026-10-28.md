# UI redo (2026-10-28)

The user: "fully redo the entire game UI ... nothing works, very laggy, text not being in the right place, menus feel
so bloated and useless". Done with file edits only. **Nothing was run, played or tested** (the user's instruction:
other agents share the editor; the user tests). The code was compiled outside Unity (`dotnet build` of the four
generated csproj files into a scratch folder: 0 errors) and `Tools/Text/check.py` reports 0 missing lines.

## Why it lagged
- `MenuScreenFx` laid full-screen *tiled* textures over every menu: a 4 x 8 px scanline tile (about 100,000 UI quads
  at 1440p), 256 px film grain moved every frame, a VHS band and a static layer. UI Toolkit draws one quad per tile.
- Every menu button carried a glow texture and scheduled about ten timed callbacks per hover (jitter, flicker, a grain
  swap); the title logo rewrote its opacity/translate every frame; a "CRT twitch" class flipped on the root.
- The pause menu ran a Gaussian depth-of-field pass (plus film grain and chromatic aberration) over the live game.

All of that is gone. Screen changes are a 0.12 s dip to black and a 0.15 s fade in. The menu post volume only
darkens, drains and vignettes.

## Why text was in the wrong place
Five redesigns had each added a stylesheet on top of the last: **12 sheets, ~5,100 lines** (Menu.uss, Revamp,
AbandonedTheme, AbandonedMenus, HorrorHud, AbandonedPanels, FieldHud, TrainingHud, ModernMenus, Remake2026,
Remake2026Layouts, HqStations). Older layers wrote `.horror-theme .x`, which out-ranks a newer plain `.x`, so later
redesigns silently lost; world screens re-added three of the sheets on their panel; four fonts were mixed (the wide
IBM Plex Mono overflowed boxes; a VT323 pixel font).

Now there is **one sheet, `Art/UI/Resources/Ui.uss` (~930 lines)**, applied once by `UiThemeAssets.Apply`. It was made
by merging the old sheets in their real load order with the `.horror-theme` / `.menu-root` prefixes stripped (so the
newest rule wins, as each redesign meant), dropping 400 selectors no code uses and every texture overlay, mapping the
older palettes (archive, h-, CRT, paper) onto the remake palette, and replacing the core components (buttons, text,
headings, sections, panels, pages, backdrops, setting rows, the Settings layout, the title) with one hand-written
section at the end of the file. Type: Saira Stencil One for big headings, Barlow Medium/Bold for everything else.
`MenuTheme.tss` imports only Unity's default theme. Ui.uss took Menu.uss's meta (same GUID), so
`UiThemeAssets.asset` still points at a sheet.

Also fixed: the hiring's dialogue box was added after the menus and drew over Settings and the creator (it now sits
just above the HUD, under every menu); toasts waited under the hiring's letterbox (they now wait until it ends).

## What was cut
- Title screen: the rotating memos, the description card, the eyebrow line, the accent rule, the key strip and the
  glitching layered logo (`MenuTitle.cs` deleted). Left: the name, one line, Continue / Save / Settings / Credits /
  (dev) Join / Quit, and one footer line with the links and the version.
- The Early Access notice shows once per version in every build (it blocked the title on every launch of a friends'
  build).
- Every page's decorative "RECORD / SUBTITLE" line and the "ABANDONED" breadcrumb; the HQ screens' masthead
  ("ABANDONED / SALVAGE DIVISION / RECOVERED RECORDS"); the pause menu's eyebrow.
- Settings: the heading's record line and subtitle, the per-page title and blurb (repeated the tab), the right-hand
  help column (now one line in the footer). "Controls+" was folded into "Controls" (7 pages, not 8).

## Left alone on purpose
- The HUD's own layout code: its per-frame work was already change-driven (loot tags cache by key).
- `MenuBackdrop` (the drifting title camera) is cheap and stays.
- `MenuEffectsConfig` still has fields for the removed effects (grain, scanlines, glow, title glitch) and their
  textures stay in the project; nothing reads them now. Remove in a later cleanup with a Unity compile.
