# Salvage mall — Unity scene setup, 0.15.5b

Implementation guide for the 0.15.5 clearance mall, dated 10 October 2026. The authoring code now covers **45 original model assets, 45 static dressing variants and 35 registered network loot variants**, with store-specific dressing, fixed-facing salvage spawn markers, work lighting and demolition dust. Read the [asset breakdown](SALVAGE_ASSET_BREAKDOWN_0.15.5.md) for each item's modelling budget, materials, prefab requirements and ready-to-use concept prompt, and the [zone design](SALVAGE_MALL_DESIGN.md) for circulation and narrative intent. Tests and visual QA remain for the user after construction.

**0.15.5b adds denser stock and demolition/packing dressing** through the additive `Mall/_SALVAGE_DENSITY` layer. Use **Tools → Abandoned → Mall → Fill Salvage Mall (0.15.5b)** to reauthor this layer on the saved scene. The existing full-library/full-mall menu below also includes it. See the [density pass guide](SALVAGE_DENSITY_0.15.5b.md) for supported stock, section/material/LOD batching and construction details.

The project uses Unity **6000.3.25f1**, URP **17.3.0**, AI Navigation **2.0.14**, Input System and Netcode for GameObjects. The approved mall retains its 56 × 48 m shell, ground floor at Y=0, upper floor at Y=4 and internal service basement at Y=−4. +Z points toward the food court. The continuous 8 m front entrance, front payout truck, surrounding district and internal service circulation remain the basis of the level.

Nordic Habitat occupies **both front-right floors**, X=32–56, Z=0–16, excluding the court notch X=32–40, Z=12–16. Heavy furniture stays downstairs; the upper department contains office sets, chairs, shelving and fabric samples. Closed administration occupies the former west upper furniture footprint, X=0–16, Z=16–32. Customer access uses the existing concourse escalators; bulky freight uses the permanent rear service ramps.

## Authoring in Unity

1. Open the Unity project in `Game/` and allow its scripts to import.
2. Select **Tools → Abandoned → Mall → Build Salvage Content (0.15.5)**. The authoring entry point creates the original shared maps, model prefabs, dressing variants and network loot, registers content and rebuilds the mall through the existing builders. It saves the scene and authors navigation/occlusion data as part of construction.
3. Tune presentation in `Assets/_Project/Data/Structure/SalvagePresentationConfig.asset`; tune generated `salvage_` LootDefinitions under `Assets/_Project/Data/Loot/` for gameplay value, weight and carry class.
4. Re-run the same menu to apply recipe or presentation changes. Existing value/weight tuning in a generated LootDefinition is retained; the model reference, mesh envelope and grip data are refreshed.
5. Review the finished level in the user's test pass. No automatic gameplay, EditMode, PlayMode, network tests or screenshot QA are part of this build request.

There is also **Tools → Abandoned → 0.15.5 → Author Salvage Asset Library** for authoring the library without rebuilding the mall. No manual setup of 35 loot prefabs is required. Scene and prefab YAML are generated by Unity authoring APIs.

## Asset library and shared PBR maps

`SalvageAssetBuilder` combines original box, low-sided cylinder and sphere recipes into persisted mesh assets by finish. Art prefabs live in `Assets/_Project/Art/Generated/Salvage0155/Models/`; fixed dressing variants live in `Assets/_Project/Prefabs/SalvageDressing/`. Network loot continues to use the normal loot prefab folder and catalog. Art and static dressing use metre-scale bottom pivots; network loot retains the existing centred gameplay pivot.

Large props have three authored LODs: a detailed near mesh, reduced handles/vents/fasteners at middle distance, and a simplified silhouette far away. Screen-relative thresholds start at **0.38 / 0.15 / 0.035**. Small board, tag and roll assets explicitly marked without LODs use one mesh. The per-item triangle figures in the asset breakdown are production estimates, not measured QA results.

Sixteen reusable finish families cover Metal, Rust, Plastic, Rubber, Glass, Circuit, Copper, Wood, Fabric, Paint, Safety, Paper, Concrete, Wrap, Net and Cable. Each uses shared **512 × 512** procedurally authored maps:

| Map | Import/channel convention | Authored wear |
|---|---|---|
| BaseColor | sRGB RGBA | Dust variation, grain, scratches, fabric weave or timber grain; opacity for wrapping/net |
| MetallicSmoothness | Linear; metallic in red, smoothness in alpha | Dust and scratches reduce smoothness; exposed metal/copper retain metallic response |
| Normal | Normal-map import | Fine surface grain and weave; stronger forms remain in geometry |
| Occlusion | Linear; Unity occlusion channel is green | Subtle shared surface variation |

Wrapping is transparent with depth writes disabled; net uses alpha clipping and two-sided rendering. Status plates, inventory cards and salvage stripes are geometry/text details layered over the shared finishes. The concept prompts are supplied for later art direction; no external AI image service or paid asset pack is required to build the current library.

## Loot metadata, focus and pickup

`SalvageProp` exposes `Category`, `ValueReady`, `SalvageValue`, `WeightKg` and `IsFocused`. Categories are **Tech, Furniture, Hardware and Material**. Apparel textiles use Material; detachers/safes use Hardware; mannequin/rack/counter use Furniture. Numeric state remains authoritative in `LootItem`, `NetworkLoot` and `LootDefinition`.

`LootPrefabGenerator` now calls `SalvageLootPrefabBuilder` for `salvage_` definitions. It automatically authors:

- Primitive or compound collision proxies and existing Rigidbody/network components.
- `InteractionAnchor`, `OutlineAnchor`, `LabelAnchor` and `CarryGrip_A` through `CarryGrip_D` attachment points.
- `OutlineVisual`, using the LOD0 mesh silhouettes and the depth-tested `Abandoned/Salvage Outline` shader.
- `SalvageProp`, with its category and outline reference already assigned.

The outline child has no colliders, Rigidbody or NetworkObject and starts disabled. Focus enables it only when the local player's `PlayerInteractor.Target` matches this object's `Grabbable`; ordinary aim occlusion still prevents selecting items through walls. Regenerating a salvage loot prefab recreates its adapter and outline automatically.

Pickup uses the existing Input System **Interact** action and aim ray. `SalvageProp.RequestPickup()` is an optional UI entry point through `InteractionService`; its `true` result means a request was sent, not that the host accepted ownership. Do not add another E listener or proximity auto-pickup trigger. Existing shared carry, host validation, pocketing and ownership transfer remain active. F1's existing debug switch enables salvage size/focus gizmos.

## Zone spawning

The normal `LootSpawnPoint` → `LootSpawnPlanner` → host `NetworkLootSpawner` flow is retained. Clients do not instantiate independent salvage loot copies.

| Zone | Installed spawn tag | Dedicated item markers | Scene placement |
|---|---|---:|---|
| A | `electronics` | 8 | Open stock/recovery pockets behind the damaged displays |
| B ground | `furniture` | 9 | Heavy furniture and handling stock outside the frontage aisle |
| B upper | `furniture` | 6 additional | Office furniture and samples; no upstairs forklift tracks |
| C | `hardware` | 6 | Clear pockets beside the tool cribs and perimeter benches |
| D | `clothing` | 7 | Central recovery pocket between displaced perimeter fittings |
| E | `concourse` | 5 | Individual pallet/dumpster/jack/crate/sorting pockets beside the staging hub |

The 35 individual salvage IDs each have a marker; six lighter B IDs repeat upstairs. Marker IDs are constrained with `allowedDefinitionIds`, and case-sensitive zone tags match their generated LootDefinitions. The seeded run planner still controls occupancy, so this marker count is not a promise that every item appears in every run. Other tenants keep secondary small-item scatter and the retained risk-prize path.

Salvage markers set **Use Authored Rotation**. The spawner uses their fixed yaw, allowing table exit alignment, shelf frontage and pallet fork openings to remain deliberate. Legacy markers without that flag retain random yaw. Markers represent the supporting surface; the existing spawn path adds half the centred definition height plus its small floor clearance. Model/dressing roots are bottom-pivoted, while network loot root positions are centred.

Static fixtures occupy the perimeter and front display islands; dedicated loot pads occupy separate recovery pockets. E reserves five dynamic stock pads and a separate crew-owned generator/light island. Only recovered cargo inside the existing truck is paid at departure. Sorting crates and fountain scrap do not settle value or duplicate payment.

## Lighting and dust

`SalvagePresentationConfig` drives the new mall presentation pass. Its defaults are authored into `MeridianPresentationConfig` before the existing atmosphere/retail lighting builders run.

| Control | Starting default | Purpose |
|---|---:|---|
| Dead / faulty fixture share | 75% / 10% | Hasty shutdown and incomplete clearance |
| Surviving retail / atrium intensity | 5.4 / 10 | Readable silhouettes between active work pockets |
| Interior exponential-squared fog density | 0.021 | Demolition haze while preserving local visibility |
| Work lamp intensity / range / outer angle | 24 / 13 m / 68° | Focused recovery illumination |
| Work lamp colour | (1, 0.93, 0.80) | Warm neutral site lighting |
| Beam opacity | 0.042 | Subtle dust-lit shaft geometry |
| Emergency intensity / range | 2.8 / 5.5 m | Amber guides at the entrance and flight approaches |
| Local dust cap | 38 per pocket; 190 total | Five concentrated demolition pockets |
| Dust particle size / drift | 0.016–0.038 m / 0.045 | Fine drywall dust suspended around active work |
| Generator volume / far range | 0.18 / 15 m | Local machinery cue through the existing audio system |

Four fixed work-light stands start at A **(4,0,12)**, C **(53,0,29)** and E **(26,0,21.8)** / **(30,0,21.8)**. Each carries two spotlight heads near Y=2.22 m and a short transparent beam; the default maximum is eight lamp heads. Work lights and battery guides use their independent clearance feed. They do not revive permanently dead retail fixtures. Their authored shadows are off, retaining the project's existing `ShadowDirector` atlas budget for eligible fixtures and player lights.

URP uses distance fog, dust ParticleSystems and saved transparent beam meshes for this effect; it has no built-in HDRP-style local volumetric fog. Local particle pockets simulate extra dust concentration without raising fog everywhere. Dust emitters prewarm, use world simulation and no particle collision. Reduced-flashing and existing mains-power behavior remain in the established retail fixture system.

The scene adds partial skylight boarding/crack overlays while retaining the sealed roof colliders. `SalvageMallDressing.DryFountain` removes separate stagnant-pool nodes where present and replaces joined water-material slots with dusty concrete, then adds shallow offcuts/dust inside the existing basin. The pedestal, bowl and collision remain intact.

## Collision and navigation

| Family | Authored collision | Physics/navigation |
|---|---|---|
| Walls, floors, gallery and structural flights | Existing shell/slab/flight colliders | Preserve structural collision and navigation updates |
| Fixed shelving, desks, chairs, cases and fences | Broad primitive/compound proxies around real volumes | No Rigidbody; fixed blockers participate in construction |
| Salvage loot | Box/compound boxes; Capsule for rolls | Dynamic Rigidbody, gravity, interpolation; existing host/owner simulation |
| Tables and open racks | Separate tabletop/legs/uprights/shelves | Keep the open spaces visible and usable |
| Cable bundles, dust sheets, net, tags, tire marks and glass slivers | Visual-only fixed dressing | No minor debris snag points; excluded as physical clutter |
| Recoverable small boards/tags/rolls | Loot collider retained | Selectable and physical even when small |
| Cosmetic collapse pieces | Existing Debris layer | Ignore player/loot collision |
| Deterministic solid rubble mound | Existing Default-layer blocking volume | Preserve runtime collapse behavior |

The new library uses simple collision proxies instead of detailed concave mesh collision. A moving non-kinematic Rigidbody must use primitive/compound or convex mesh shapes; non-convex MeshColliders remain an option only for appropriate fixed environmental geometry. Heavy/Huge loot retains the standard generator's speculative continuous-collision policy and stable mass limits. Remote non-simulating copies remain kinematic under the existing network carry system; no NetworkRigidbody is added.

Keep at least **2.4 m** through permanent carry lanes, the 8 m front entrance and full flight approaches. The front shop aisle Z=4–8, middle shop aisle Z=20–24 and court ring remain the circulation backbone. Depicted forklift tracks are flat visual geometry and appear only downstairs. Place tall barriers in side pockets and use the existing `MallRouteClearance` authoring policy.

The existing `NavMeshSurface` remains on Mall, collects children and uses **Physics Colliders**. Player, Loot, Debris and Ignore Raycast layers are excluded; existing exterior/truck/roof/navigation exclusions remain. Navigation and occlusion data are authored after fixed geometry/collision. No per-frame NavMesh rebuild or new loot obstacle lifecycle is introduced.
